# Security Policy

## Supported versions

Security fixes are currently handled on the default branch. There are no separately maintained release branches at this time.

## Reporting a vulnerability

Please do not disclose exploitable details in a public issue. Report suspected vulnerabilities privately through the repository owner's GitHub contact or a private GitHub security advisory if that feature is enabled for this repository.

Include:

- a short description and potential impact;
- the affected file, workflow, or behavior;
- minimal reproduction steps that do not expose real credentials or personal data; and
- any suggested mitigation.

Please redact tokens, API keys, cookies, credentials, private URLs, and customer data. If a secret may have been exposed, revoke or rotate it immediately and mention only the secret type and affected location in the report.

We will acknowledge reports when possible, investigate in good faith, and coordinate disclosure after a fix or mitigation is available. Please allow reasonable time for triage before public disclosure.

## Scope

This policy covers the audit-skill repository and its documentation. Reports about a third-party repository being audited should be sent to that repository's maintainers.
